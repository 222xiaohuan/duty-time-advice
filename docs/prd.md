# Duty Time Advice 排班时间报备功能需求说明书

版本：V1.0 Final Demo  
用途：供 HKJC 场景演示及标准产品研发理解业务逻辑，非生产交付文档。

## 1. 产品定位

排班时间报备（Duty Time Advice）是排班系统的前置约束数据收集模块。员工、主管及模板任务在排班前录入可排、不可排或优先排时段，供排班引擎和人工排班参考。

Demo 使用 Mock 角色、模拟员工与模拟班次，重点演示组织与员工类型参数、周期模板、可排性报备、截止锁定和班次冲突校验。审计/操作日志、导入导出、消息提醒、审批、场地与特殊日期差异化均只保留标准产品扩展说明。

## 2. 统一术语与状态

### 2.1 命名规则

- 英文业务名词统一使用 `Rosterability`。
- 中文统一使用“可排”、“不可排”和“可排性”。
- 表名、枚举名、接口名、页面文案和文档必须保持一致。

### 2.2 可排性状态

- `ROSTERABLE`：可排。
- `UNROSTERABLE`：不可排。
- `PRIORITY_ROSTERABLE`：优先排；表示该时段可排且在排班决策中优先考虑。
- `STANDBY`：后备待命，作为标准产品预留状态，Demo 默认不启用。

`locked` 是记录的只读标记，不是可排性状态。锁定后必须保留原有 `ROSTERABLE`、`UNROSTERABLE` 或 `PRIORITY_ROSTERABLE` 语义。

### 2.3 来源编码

- `EMP_SUBMIT`：员工提交。
- `MGR_MAINTENANCE`：主管维护。
- `TEMPLATE_GEN`：模板任务生成。
- `EXTERNAL_SYNC`：外部系统同步，作为标准产品预留。
- `BULK_IMPORT`：批量导入，作为标准产品预留。

状态和来源均由租户级字典维护。状态字典包含多语言名称、展示色值、排班许可标记、员工是否可自主选择和启用标记；排班规则读取许可标记，不按名称硬编码。来源字典包含图标和编辑权限标记，来源用于控制员工或主管能否直接修改记录。审批流转状态独立于可排性状态，Demo 不预置审批类状态。

## 3. 核心设计原则与总体架构

### 3.1 设计原则

- 业务规则由主数据与参数驱动，不在页面中硬编码状态判断。
- 当前版本不使用的能力默认关闭，关闭时不展示配置入口、页面控件或校验分支。
- 可排性状态与记录来源分开表达：颜色表达状态，图标和图例表达来源。
- 为场地、审批、外部同步和特殊日期预留字段与开关，启用时沿用现有记录、日志和接口结构。
- 标准产品对新增、修改、删除、生成、导入和同步动作写入不可修改的追加审计日志；Demo 不实现审计/操作日志，导入和同步只保留正式产品编码预留。

### 3.2 数据分层

| 层级 | 内容 | 维护方 | 扩展方式 |
| --- | --- | --- | --- |
| 主数据层 | 可排性状态字典、可排性来源字典；公司日历和场地只作正式产品对接说明 | 租户管理员 | 新增字典项，不修改核心流程 |
| 参数层 | 租户、组织与员工类型参数；场地、审批、特殊日期开关固定关闭 | 租户管理员、实施顾问 | 按配置维度下发参数 |
| 业务数据层 | 员工可排性记录、周模板、模板条件、模拟班次及审批预留字段 | 员工、主管、模板任务 | 新增来源或状态承载后续能力 |
| 审计层 | 操作日志、变更前后快照和审批动作日志预留 | 标准产品系统自动写入 | 随业务维度扩展字段 |

### 3.3 可视化表达规则

日历色块颜色来自可排性状态字典的 `color_hex`；`ROSTERABLE`、`UNROSTERABLE` 与 `PRIORITY_ROSTERABLE` 使用各自状态颜色，`locked` 使用灰色只读视觉。来源不占用颜色语义，使用色块角落图标、页面图例和详情提示表达。详情和导出占位显示状态编码、状态名称、来源编码与来源名称；标准产品审计记录也应显示这些字段，图例按当前启用的字典项动态生成。

## 4. 组织与员工类型参数

生效参数维度为“租户 + 组织 + 员工类型”。管理员创建包含全部员工类型规则的命名参数方案，批量应用到一个或多个组织；应用时将规则写入各组织的生效参数组。方案一经创建即只读，需要差异时复制为新方案并重新分配，未重新分配的组织保持原配置。人工直接修改生效参数组会解除该组织的方案关联。Demo 应用后立即生效；标准产品应提供方案版本、生效日期与历史规则查询，以免后续配置变更影响历史业务日的解释。演示种子额外提供 8 个未绑定方案的组织，供管理员练习批量绑定与更换；这些组织暂不预置员工。

| 参数 | Demo 规则 |
| --- | --- |
| `cutoff_days` | 提前 N 个自然日锁定（包含当天），取值 0至30；例如今天为 11 月 17 日且配置 3，则锁定 17、18、19 日 |
| `priority_roster_enable` | 组织与员工类型级优先排班模式开关；0 关闭，1 开启 |
| `baseline_rule` | `BASE_ROSTERABLE` / `BASE_UNROSTERABLE` |
| `submit_mode` | 四种提报模式，受基线联动校验 |
| `emp_edit_enable` | 是否允许员工自主编辑 |
| `template_auto_gen_enable` | 定时生成预留，Demo 固定为 0 |
| `auto_gen_range_week` | 经理手动生成未来完整周数，页面可配置 1 至 12，必填 |
| `auto_gen_weekday` | 定时生成预留，Demo 固定为空 |
| `auto_gen_time` | 定时生成预留，Demo 固定为空 |
| `conflict_check_mode` | Demo 固定 `STRONG_BLOCK`；豁免模式仅作标准产品预留 |
| `field_site_enable` | 预留，Demo 固定关闭 |
| `enable_approval` | 预留，Demo 固定关闭 |
| `special_tag_diff_enable` | 预留，Demo 固定关闭 |

### 4.1 基线与提报模式合法矩阵

| 基线规则 | 允许的提报模式 | 禁止的提报模式 |
| --- | --- | --- |
| `BASE_ROSTERABLE` | `MODE_ONLY_UNROSTERABLE`、`MODE_ALL_STATUS`、`MODE_NO_SUBMIT` | `MODE_ONLY_ROSTERABLE` |
| `BASE_UNROSTERABLE` | `MODE_ONLY_ROSTERABLE`、`MODE_ALL_STATUS`、`MODE_NO_SUBMIT` | `MODE_ONLY_UNROSTERABLE` |

前端对非法选项置灰，后端保存时再次校验。员工所属组织和员工类型的生效参数启用 `priority_roster_enable=1` 后，默认 `BASE_UNROSTERABLE` 可维护 `ROSTERABLE` 与 `PRIORITY_ROSTERABLE`，默认 `BASE_ROSTERABLE` 可维护 `UNROSTERABLE` 与 `PRIORITY_ROSTERABLE`；`MODE_ALL_STATUS` 在该组合开启时包含三种状态。该组合关闭时不允许创建或修改 `PRIORITY_ROSTERABLE`；既有记录仍可查看。不同员工类型可独立开启或关闭。

### 4.2 截止与锁定

提前锁定统一按香港自然日计算：

`locked = business_date < hk_today OR (cutoff_days > 0 AND business_date <= hk_today + cutoff_days - 1 个自然日)`

实现口径：锁定状态在每次读写时由后端按当前香港日期和参数实时计算，是否只读以计算结果为准；`locked` 字段仅作展示用缓存，不作为校验依据，也不覆盖原可排性状态。`cutoff_days` 包含当天，例如香港今天为 11 月 17 日且配置 3，则只读日期为 17、18、19 日，20 日起的未来日期仍可编辑；配置 0 表示不额外锁定今天及未来日期，但过去日期仍只读。Demo 不提供员工或主管越过锁定窗口修改可排性记录的能力。

### 4.3 基线规则的业务含义

全职类员工通常大多数时间可到岗，可将基线设为 `BASE_ROSTERABLE`，员工只维护少量 `UNROSTERABLE` 或 `PRIORITY_ROSTERABLE` 时段；小时工或兼职员工时间不固定，可将基线设为 `BASE_UNROSTERABLE`，员工主动维护 `ROSTERABLE` 或 `PRIORITY_ROSTERABLE` 时段。维护与默认基线相同的时段没有业务意义，Demo 在保存时提示“已默认全部不可排，无需维护不可排时间”或“已默认全部可排，无需维护可排时间”，并拒绝写入。客户可以按实际用工情况自由配置，产品不强制把员工类型绑定到某个基线。

### 4.4 特殊日期差异化预留

Demo 中 `special_tag_diff_enable` 固定为 `0`，不建立日期标签、日期绑定、差异参数、筛选或专项视图。正式产品如需节假日、赛事日等差异化规则，应对接公司标准日历设置。

### 4.5 审批流程预留

Demo 中 `enable_approval` 固定为 `0`，记录提交后直接生效，不展示审批按钮、审批状态、审批人或审批意见。正式产品启用后可支持员工提交审批、主管审批、驳回后重新提交，并将审批状态、审批人、审批时间和意见写入同一记录与审计日志；审批未通过的记录不参与排班约束校验。

## 5. 周期模板

### 5.1 模板结构

Demo 只实现“周固定周期模板”。一个模板覆盖周一至周日，每天可配置零条或多条时段；每条明细包含：

- 星期值 `weekday`（1至7）。
- 开始时间与结束时间。
- 跨日偏移 `end_day_offset`（0 或 1）。
- 可排性状态、备注及预留场地编码。

模板可配置生效开始日期和可选失效日期。

### 5.2 条件匹配

Demo 仅使用以下员工属性匹配模板：

- 组织。
- 员工类型。
- 岗位编码。

同一条件内的非空字段为 AND 关系。多条模板同时命中员工时，按条件优先级升序选择；优先级相同时，按模板更新时间倒序、主键倒序选择，保证结果确定。

### 5.3 生成规则

- Demo 不运行定时生成任务。管理员在组织与员工类型参数页配置 `auto_gen_range_week`，取值 1 至 12。
- 经理在所辖组织的可排性视图顶部操作区点击“生成可排时段”。后端按每名员工所属组织与员工类型的参数值，从下一个完整自然周（香港时间周一 00:00）起，生成未来对应周数的记录；不要求经理在点击时再次输入周数。
- 点击时按当前有效的组织、员工类型和岗位条件重新匹配每名员工的模板，按优先级选择实际关联模板；仅对经理所辖组织的员工生成，不使用其他组织的数据。
- 生成记录的 `source_code=TEMPLATE_GEN`，并回填 `template_id`。
- 生成记录回填 `template_id` 和 `template_item_id`。
- 去重键为“租户 + 员工 + 业务日期 + `template_item_id`”，**不区分是否已软删除**：该键已存在记录（含已人工修改、已被删除的记录）时不再重新生成。
- 员工或主管已人工修改的记录不被后续手动生成覆盖。
- 目标业务日期已到截止时间（已锁定）时跳过；标准产品应在审计备注中记录跳过原因。
- 生成 `UNROSTERABLE` 记录时，同员工同业务日存在时长大于 0 的模拟班次则跳过该条；标准产品应在审计备注中记录跳过原因。组织未启用优先排班模式时，模板中的 `PRIORITY_ROSTERABLE` 记录跳过并返回状态未启用原因。
- 经理页生成按钮展示生成结果：成功新增数、已存在跳过数、锁定跳过数、班次冲突跳过数及对应员工和日期的原因。重复点击不得重复生成。
- Demo 不写入审计日志；标准产品的自动与手动生成应写入审计日志，自动生成的操作人为固定系统账号。

### 5.4 模板微调与覆盖策略

手动生成必须幂等，按“租户、员工、业务日期、模板明细”去重，已存在记录（包括已软删除和已人工修改的记录）不再生成。再次点击不覆盖员工或主管已经修改的记录；目标日期已锁定，或生成 `UNROSTERABLE` 时命中当日正时长模拟班次，则跳过该条并返回跳过原因。标准产品再将原因写入审计备注。

## 6. 可排性时段

### 6.1 基本结构

一条记录由员工、业务日期、可排性状态、来源、开始时间、结束时间、备注、锁定标记与审计字段构成。同一天可存在多条时段。

### 6.2 跨午夜

支持例如 22:00 至次日 02:00 的跨午夜时段。`business_date` 统一归属开始时间所在日期，即跨午夜后的凌晨部分仍归属前一个自然日。

### 6.3 模拟班次冲突

Demo 增加模拟班次数据。创建或修改 `UNROSTERABLE` 记录时，后端必须检查：

1. 同一员工。
2. 同一 `business_date`。
3. 存在未删除且 `duration_minutes > 0` 的工作班次。

三个条件同时成立时禁止保存，不允许豁免，并返回明确提示：

> 该员工当日已存在工作班次，不能调整为不可排。

Demo 按整个业务日期校验，不仅校验时间区间是否重叠。

### 6.4 备注与正式产品同步预留

每条时段支持备注，用于记录原因或特殊约定，并在详情和导出占位中展示。标准产品可由外部业务系统推送锁定时段，来源标记为 `EXTERNAL_SYNC`，默认只读并记录同步日志；Demo 不实现外部接口和审计记录。

### 6.5 审批字段预留

可排性记录预留 `approval_status`、`approver_id`、`approved_at` 和 `approve_comment` 字段。Demo 保持空值，不参与校验和展示；正式产品启用审批后由审批流程写入。

## 7. 角色与页面

### 7.1 Mock 角色

- `admin`：组织参数与字典；管理员视图不展示排班时间报备和周模板页面；审计日志属于标准产品预留。
- `manager`：员工可排性视图和周模板页面；可为管辖范围内员工新增、修改、删除未锁定的可排性记录（来源 `MGR_MAINTENANCE`，同样受截止锁定与班次冲突校验约束）；维护模拟班次；手动生成模板记录。
- `employee`：查看与维护本人未锁定的时段（参数 `emp_edit_enable=0` 时只读）。

### 7.1.1 Mock 身份传递

Demo 不做登录与 JWT。前端角色切换后，每次请求携带请求头：

- `x-mock-role`：`admin` / `manager` / `employee`。
- `x-mock-user-id`：当前员工 ID（`employee` 必填；`manager` 和 `admin` 使用种子中的固定账号 ID）。
- `x-mock-org-id`：`manager` 的管辖组织 ID（Demo 中主管管辖单个组织）。

后端以请求头确定操作人、数据范围和 `operate_source`，所有权限判断必须在后端执行。`.env` 中的 `JWT_SECRET` 本期不使用。

### 7.2 核心页面

1. 管理员组织参数配置页：按员工类型维护命名参数方案；组织列表支持搜索、多选及批量应用方案。点击应用后在确认弹框中核对目标方案的员工类型规则、首次绑定/更换方案/重新应用数量；若选中有参数但未绑定方案的组织，另提示“覆盖单独配置”。可展开查看逐组织字段差异；取消不写入，确认后立即生效。列表底部不显示常驻应用预览。例外组织通过复制方案处理，组织列表从接口读取，不写死演示组织。
2. 主管周模板与条件匹配页。
3. 员工周日历报备页，含快捷操作：一键复制上周记录、一键复制本周记录至下周、批量勾选多个日期统一设置可排性状态。快捷操作逐条走与手工录入相同的后端校验（截止锁定、班次冲突、提报模式），失败项逐条返回原因，不整体回滚。
4. 主管多视图可排性日历页，用于查看和维护可排性记录、手动生成模板记录；模拟班次在此只读展示，供冲突判断参考。单日全员模式按员工行展示 00:00–24:00 时间轴；单人周模式左侧展示可上下滚动的员工列表，右侧按周日到周六逐日展示所选员工的 00:00–24:00 时间轴。两种时间轴均可选择可排/不可排状态，在未锁定行上拖拽出时段，确认后创建；点击已有时段打开编辑面板，支持时段/全天切换、时间、跨午夜和备注编辑。时间轴按员工所属组织与员工类型的 `baseline_rule` 显示浅蓝色“默认全部可排”或浅灰色“默认全部不可排”背景，每行仅在色块左下角以小号斜体文字标注一次；无有效参数时使用中性底色，不推断默认状态。背景仅表达默认基线，实际记录仍用状态字典颜色展示，其中可排状态使用 `#4a90e2` 蓝色，不可排状态使用中灰色。员工名称下方只展示员工类型与岗位等人员属性；过去日期整行置灰并增加斜线纹理标记，达到提前锁定截止的日期整行置灰并在“已提前锁定可排时间”旁显示锁形图标；两类日期均只读且不允许新增、拖拽、修改或删除，并在时间轴默认基线文字位置分别提示“无法修改过去日期的可排时间”或“已提前锁定可排时间”；未来未锁定日期继续显示“默认全部可排/默认全部不可排”。锁定行中的既有记录和模拟班次仍可查看。拖拽按 15 分钟对齐，跨午夜时段归属开始日；保存和删除继续使用现有后端权限及冲突校验。组织周模式在每个日期格内将可排、不可排和优先排记录按开始/结束时间显示为彩色时段块，块内显示时长；排班时间独立排列在时段块下方，悬浮时分别显示状态、开始时间、结束时间、跨午夜标记和时长。
组织周的空单元格左上角显示“+”；点击单元格任意位置打开可排性时段维护弹框，点击已有时段进入该记录编辑。弹框中的可维护状态按员工默认基线和所属组织与员工类型的优先排开关过滤：默认不可排时显示可排及已启用的优先排，默认可排时显示不可排及已启用的优先排。弹框支持时段、全天、跨午夜、备注及已有记录编辑/删除；锁定日期和只读来源不允许修改。页面底部不再显示独立的可排性记录和模拟班次详情区，组织周单元格下方仍展示排班时间。
组织周的过去日期列头与员工单元格使用灰底斜线，提前锁定的员工单元格使用灰底和锁图标；没有有效参数的日期同样只读。只读单元格不显示新增“+”，点击空白处不能打开维护弹框；已有记录和排班时间保持可见，已有记录可打开只读详情。提前锁定按每名员工的有效参数分别计算，不把整列统一锁定。
5. 独立的主管模拟排班页：参考员工行、周一至周日列的周排班表，在日期格内展示模拟班次。点击日期格“+”弹出可搜索的班次清单（代码、名称、起止时间和时长），选择一项即按该员工与日期排入；点击已排班次打开弹框修改或删除。页面底部不显示独立班次维护区。Demo 使用固定的模拟班次选项，包含常见班、跨午夜班和零时长休息；正式产品对接班次主数据。可排性记录以细色条标记在对应员工和业务日期格中，不同状态的时段按当天起止时间定位在同一条水平线上，颜色取状态字典的展示色值，支持多时段及跨午夜提示；标记只读，点击可查看状态与时间及时长。模拟班次悬浮提示显示开始时间、结束时间和时长，时长使用 `h` 单位（例如“8h”）。排班页仅操作模拟班次，不修改可排性记录。
6. 审计日志页属于标准产品预留，Demo 不实现。

### 7.3 管理端视图与权限

主管可排性页面提供单日组织总览、单人周视图和组织周视图，支持按组织、员工类型、岗位、来源和状态筛选，并只读展示模拟班次；主管同时维护周模板及组织、员工类型、岗位条件。独立模拟排班页按员工与自然周展示模拟班次及可排性色条；班次维护只在该页进行。管理员页面仅提供组织参数，不展示排班时间报备和周模板入口。组织月、连续双月视图和特殊日期专项视图属于正式产品预留，本期主管页面不展示组织月入口。员工只能查看和维护本人数据；主管只能查看和维护所辖组织员工数据；管理员可查看全量数据，权限判断全部在后端执行。

## 8. 导入导出和消息提醒边界

### 8.1 导入导出

Demo 只在相关页面放置导入和导出按钮作为功能占位，点击后提示“Demo 版本未开放，标准产品提供批量导入导出能力”。Demo 不提供文件解析、导入任务、数据写入和导出文件后端接口。

标准产品需支持可排性记录、模板、模板条件和参数的批量导入导出，并提供逐行校验结果。

导入导出能力的稳定键使用状态编码和来源编码。Demo 的按钮只显示“Demo 版本未开放，标准产品提供批量导入导出能力”，不上传、解析、写入、下载或建立导入任务。

### 8.2 消息提醒

Demo 不实现消息发送、消息模板或调度逻辑。页面可保留说明性占位，表明标准产品将对接公司独立消息提醒模块，支持提交提醒、截止预警和变更通知。

## 9. 预留能力

### 9.1 特殊日期差异化

Demo 仅保留 `special_tag_diff_enable` 字段，默认值和固定值均为 0，不提供日期标签字典、标签绑定、差异参数、页面筛选或专项视图。标准产品如需特殊日期规则，应对接公司现有日历设置，不在 Demo 内自建日历主数据。

### 9.2 场地与审批

`field_site_enable` 和 `enable_approval` 只做字段预留，Demo 固定关闭，不展示入口、不执行业务逻辑。

## 10. 审计日志（标准产品预留）

Demo 不实现审计/操作日志接口、页面或写入逻辑。以下内容只作为标准产品扩展说明，后续启用时再落地。

以下动作必须写入审计日志：

- 可排性记录新增、修改、删除。
- 参数与模板配置变更。
- 模板条件变更。
- 自动或手动生成记录。
- 模拟班次新增、修改、删除。

日志支持按操作时间范围、员工、组织、可排性状态、记录来源和动作类型查询。`status_code` 与 `source_code` 仅在 `target_type=record` 的记录日志中填写：新增、修改取变更后值，删除取变更前值；其他对象的日志留空。修改前的状态和来源仍可从 `before_json` 追溯。日志为不可修改的追加数据，不提供修改或删除接口。

当前预留模型包含租户、组织、员工、业务日期、对象类型与 ID、动作编码、操作人、操作时间、变更前后 JSON、状态、来源、备注，以及 `operate_source`（操作者角色或系统）。配置变更可不关联员工和业务日期；成功生成的每条记录以 `target_type=record`、`action_code=TEMPLATE_GEN` 记录。已匹配模板但因锁定或班次冲突跳过时，标准产品通过 `target_type=template`、模板 ID、员工、业务日期和备注记录跳过原因；此时状态与来源筛选字段留空。独立的“操作入口”（例如页面、导入或定时任务）尚无预留列，属于正式产品实施时的结构扩展，不能把它与 `operate_source` 混为一项。日志保留版本快照，支持排班纠纷追溯；Demo 不产生任何审计数据。

## 11. 校验与约束规则

| 规则 | 触发时机 | 处理方式 |
| --- | --- | --- |
| 参数联动防呆 | 保存组织与员工类型参数 | 前端置灰非法组合，后端强校验并返回明确提示 |
| 模拟班次冲突 | 创建或修改 `UNROSTERABLE` | 同员工同业务日存在 `duration_minutes > 0` 的未删除班次时禁止保存 |
| 提前锁定 | 香港今天起连续 `cutoff_days` 个自然日（包含当天），过去日期始终只读 | 记录只读，保留原可排性状态 |
| 模板幂等 | 经理手动生成 | 按员工、业务日和模板明细去重，不覆盖人工修改 |
| 版本留存（标准产品） | 每次记录变更 | 审计日志保存变更前后快照；Demo 不实现 |
| 审批生效（预留） | 正式产品启用审批后 | 仅已通过记录参与排班约束，本 Demo 不生效 |

## 16. Demo 验收边界

Demo 必须完成：参数防呆、周期模板、条件匹配、经理点击生成未来 1 至 12 周时段、截止锁定、跨午夜、模拟班次冲突、角色切换和多视图日历。
